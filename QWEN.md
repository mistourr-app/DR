# Dungeon Card Crawler — контекст проекта

## Обзор

Dungeon Card Crawler — мобильный пошаговый dungeon crawler в жанре rogue-lite. Это PWA на ES-модулях и HTML5 Canvas без игрового сервера и базы данных.

## Архитектура

| Файл | Назначение |
|---|---|
| `main.js` | Точка входа, canvas, resize, game loop, service worker |
| `config.js` | Размеры canvas и состояния приложения |
| `state.js` | `runState`, `metaState`, run ID, localStorage |
| `registry.js` | Уровни, клетки, враги, валидация уровней |
| `run.js` | Генерация забега, движение, взаимодействия, передача хода |
| `combat.js` | Урон, атакующие и защитные бонусы |
| `enemyAI.js` | Атаки врагов и карты угроз |
| `bossAI.js` | Три профиля AI босса и бонусные клетки |
| `renderer.js` | Canvas-рендеринг, камера и threat maps |
| `ui.js` | Меню, экраны результата, инвентарь |
| `animation.js` | Последовательная очередь анимаций и таймеры забега |
| `events.js` | Шина событий |
| `utils.js` | Seeded PRNG и генерация объектов |
| `tutorial.js` | Фиксированный tutorial из 14 шагов |
| `server.js` | Локальный статический сервер для разработки |
| `admin.html` | Встроенный редактор уровней |

## Состояния и фазы

```text
BOOT → META_HUB → RUN_PLAYING → RUN_SUMMARY / RUN_VICTORY → META_HUB
```

- `dungeon`: вертикальное движение по рядам вверх, 5 колонок.
- `boss_arena`: последние два ряда, горизонтальные ходы игрока и босса.
- `turnOwner`: `player` или `processing`; `boss` используется только как внутренний переходный режим.
- В `boss_arena` выстрел из арбалета можно сделать до перемещения; перемещение или атака клеткой передает ход боссу.
- В обычном забеге и боссфайте — не более одного выстрела из арбалета за ход игрока.
- `runId` защищает анимации и таймеры от действий предыдущего забега.

## Правила игры

- HP игрока: 20, энергия: 10.
- Арбалет: урон 3, дальность 3, обычно три заряда; `debug_boss` стартует с десятью.
- В инвентаре два слота атаки и два слота защиты.
- Бесплатный ход — соседняя клетка следующего ряда.
- Стоимость прыжка: `max(0, расстояние по X - 1)` энергии.
- Враги с ряда, который игрок покидает, атакуют до движения при наличии видимости.
- Бонусы атаки расходуются первыми; затем защита поглощает урон; остаток уменьшает HP.
- Защита списывается только на фактически поглощённый урон.
- Одинаковый `?seed=` даёт одинаковую процедурную карту. Seed `0` допустим.

## Уровни

| ID | Ряды | HP босса | Назначение |
|---|---:|---:|---|
| `tutorial` | 13 | x1 | Фиксированный tutorial |
| `test_arena` | 6 | x1.5 | Скрытая тестовая арена |
| `debug_boss` | 3 | x1 | Скрытая арена для боссфайта |
| `sector_1` | 30 | x1.2 | Обычный уровень |
| `sector_2` | 50 | x1.5 | Повышенная сложность |
| `core` | 75 | x5 | Финальный уровень |

`test_arena` и `debug_boss` скрыты в registry и не появляются в обычном меню. Админка может менять текущий список, порядок и visibility в рамках страницы, но постоянное изменение требует экспорта в `registry.js`.

## Мета-состояние

Сейчас сохраняются только золото и задел `upgrades` в `localStorage`; порядок и видимость уровней хранятся отдельно. Золото за подбор и завершение забега уже начисляется, остальные части `META.md` — план развития.

Ключи хранения:

- `dcc_meta`
- `dcc_data_version`
- `levelOrder`
- `levelVisibility`

При смене `DATA_VERSION` (сейчас `2`) ключи `levelOrder` и `levelVisibility` очищаются; повреждённый JSON игнорируется. Прогресс отдельных забегов и разблокировки не сохраняются.

## PWA и стили

- `manifest.json` и `sw.js` включены в приложение.
- Service worker использует network-first для навигации с fallback на precached response, затем `index.html` для неизвестных navigation requests; остальные локальные ресурсы — cache-first.
- Версия cache: `dungeon-crawler-v24`; `styles.css` — отслеживаемый артефакт, генерируемый `npm run build:css`.
- UI перерисовывает верхнюю панель при смене состояния; инвентарь босса отображается только в `boss_arena`, а слоты босса используют компактный размер.
- В игровом UI значения и inline-цвета экранируются/whitelist-проверяются перед вставкой в HTML.
- Marker версии в игре — `v24`; кнопка возврата из встроенного редактора ведёт в `index.html`.
- Tailwind собирается локально; CDN в игровом UI не используется.

## Запуск и проверки

```bash
npm ci
npm run build:css
npm start
```

Открыть `http://127.0.0.1:5500`. Для повторяемого забега использовать `?seed=12345`; для прямого запуска уровня — `?level=sector_1`.

```bash
npm test
npm run lint
npm run typecheck
npm run build:css
git diff --check
```

CI выполняет `npm ci` на Node.js 20 и проверяет отсутствие дрейфа `styles.css`. `typecheck` использует `allowJs` без `checkJs`, поэтому это проверка конфигурации TypeScript, а не полная типизация JavaScript. Админ-панель открывается пятью быстрыми кликами по заголовку меню; её изменения требуют экспорта в `registry.js`.

## Валидация и безопасность

- Уровень: `id` до 64 латинских символов, `name` до 100 символов, `rows` — целое 3–100, `bossHpMultiplier` — число 0.1–100.
- Для обычных уровней `chances` содержит восемь числовых значений 0–1 с суммой не больше 1; числовые строки и нечисловые значения отклоняются.
- Tutorial layout проверяет 5 клеток на ряд, известные типы/enemyType, значения данных и размещение `attack_cell` только в арене.
- Админка экранирует ввод и ограничивает числовые поля; HTML-скрипты не входят в ESLint.
- `server.js` слушает только `127.0.0.1`, проверяет lexical/real path, dotfiles, traversal, null/backslash, методы и security headers; это dev server, не production reverse proxy.
- ESLint использует `eslint:recommended` с отключёнными `no-unused-vars`/`no-empty`; inline-скрипты HTML не проверяются.
- Автотесты покрывают combat, PRNG/генерацию, gameplay lifecycle, boss arena, localStorage/валидацию и HTTP/security; browser/PWA и ручной tutorial остаются отдельными проверками.

## Важные ограничения

- `tutorial.js`, layout tutorial, HP и разрешённые клетки не изменяются.
- Игровые ассеты рисуются программно на canvas.
- Локальный сервер не предназначен для публичного размещения.
- Перед изменением баланса нужно обновить `registry.js`, тесты и документацию.

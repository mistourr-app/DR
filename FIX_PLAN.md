# План исправлений Dungeon Card Crawler

## 1. Контекст

- Рабочая ветка: `fix/gameplay-stability-and-tooling`
- Базовая ревизия: `635c09b11f23656c0ef20a431bfcc215b2c12ebc`
- Проект: статическая браузерная PWA на ES-модулях и HTML5 Canvas.
- Локальный сервер: `node server.js`, адрес `http://127.0.0.1:5500`.
- Автоматический commit и push не выполняются без отдельной команды.

## 2. Ограничения

- `tutorial.js`, layout tutorial, его 14 шагов, HP и разрешённые клетки не изменяются.
- Исправления gameplay выполняются в общих модулях, а не через отдельный tutorial-режим.
- Не добавляется новый игровой режим или новая система прогрессии.
- Публичное размещение локального dev-сервера не предполагается.

## 3. Согласованные правила боя

1. Сначала расходуются атакующие бонусы.
2. Затем применяется базовый урон.
3. Защита поглощает урон и уменьшается на поглощённую часть.
4. Остаток урона уменьшает HP цели.
5. Атакующий бонус расходуется, даже если защита полностью его перекрыла.
6. Правило одинаково для ближнего боя, арбалета, клеток атаки и атак босса.

## 4. Выполненные изменения

### P0: блокирующие ошибки

- В `run.js` исправлены ключи бонусов атаки и защиты.
- Границы карты, существование клетки, стена и энергия проверяются до списания ресурсов и передачи хода.
- `server.js` слушает только `127.0.0.1`, проверяет корень проекта, реальный путь файла, скрытые файлы, traversal, null и backslash.
- Разрешены только `GET` и `HEAD`; добавлены MIME, charset, security headers и `Cache-Control`.
- Сервер остаётся loopback dev-сервером и не предназначен для публичного размещения.

### P1: состояние и gameplay

- Добавлен `runId`; устаревшие анимации и таймеры не меняют новый забег.
- `handOffToBoss()` и `bossTurnScheduled` не допускают повторную передачу хода.
- Выделены общие расчёт атаки, расход attack/defense bonuses и урон игроку.
- Seed `0`, отрицательные и нечисловые значения обрабатываются; процедурные уровни используют общий PRNG.
- Resize пересчитывает координаты клеток, игрока, босса, камеры и floating texts.
- Повреждённый `localStorage` игнорируется, безопасные значения используются по умолчанию.
- В обычном забеге и boss arena действует лимит: не более одного выстрела за ход; выстрел в boss arena не передаёт ход, а перемещение или атака клеткой — передаёт.
- Админка экранирует пользовательские значения, ограничивает числовые поля и проверяет определения уровней.
- Валидация отклоняет числовые строки в `chances`, неверные типы клеток, enemyType, значения и сумму вероятностей.
- Полный инвентарь бонусов больше не оставляет ход без завершения.

### P2: интерфейс, PWA и качество

- Исправлены золото, угрозы нескольких врагов, full-inventory fade и free melee без энергии.
- Камера, floating texts и тактические линии используют delta-time; линия выстрела рисуется поверх карточек игрока и босса.
- Service worker зарегистрирован; cache version — `dungeon-crawler-v25`; offline fallback сохраняет precached `admin.html`.
- `styles.css` собирается локально из `src/input.css`, отслеживается в репозитории и проверяется CI; CDN в игровом UI отсутствует.
- Добавлен PNG graphics pipeline: `GRAPHICS.md`, `assets/manifest.json` (`1125×2436`), loader с `cover/tile/9-slice/sprite` и procedural fallback; canvas стал DPR-aware.
- Добавлены `node:test`, regression-тесты gameplay и state/server/graphics, `npm run lint`, `npm run typecheck`, `npm run graphics:check` и GitHub Actions на Node.js 20.
- `typecheck` не включает `checkJs`; lint не проверяет inline JavaScript в HTML.
- Синхронизированы `README.md`, `QUICKSTART.md`, `MOVEMENT.md`, `META.md`, `QWEN.md` и этот план.
- Удалены только `.qwen/settings.json` и `.qwen/settings.json.orig`; остальные упомянутые старые каталоги уже отсутствовали в базовом commit.
